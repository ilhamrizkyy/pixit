## THE DIAGNOSIS, in one paragraph

The owner said the category chips are "boring". They are, and the cause is not taste.
`globals.css` still carries this comment above `.pixl-field`:

> *"A field in the CONTENT area, which is plain shell — not the toy. The toy is the nav
> and the sidebar."*

That describes the architecture DESIGN.md §1 retired on 2026-08-29. **The search field and
the chip row are the last two pieces of the pre-board design still in place.** The board
was rebuilt around them and they were never revisited. Everything else on the device got a
construction paragraph: the knob, the drum, the rail, the badge, the mini screen. The
glass got none.

And a correct rule got over-read. §1 says chips are flat because they are drawn on glass.
True. But "flat" collapsed into "generic", and the device itself disproves that: the LCD
readout, the dot matrix and Pixel Materialize are all flat, all drawn, and all
unmistakably this product. A display has its own vocabulary — lit and unlit, segments,
printed legend, video-reverse. The header uses none of it. **No rule in DESIGN.md requires
the glass to look like a web form.**

### 1.4 The travelling fill, specified

The one design move that fixes 11 and helps 8, without breaking the single-accent rule.

- One absolutely positioned capsule behind the row, inside `.pixl-chips`, painted in the
  **selected chip's own `--cat` tint**. Not an accent bar: colour still indexes, selection
  is still mass.
- `.pixl-chip[aria-selected="true"]` drops its own background. The moving capsule is the fill.
- Position with `transform: translateX(N) scaleX(N)` on a 1px base, `transform-origin: left`.
  **Never `width`** (see 3.3). Reuse the helper `DetailBar.tsx:95-119` already has.
- Recipe: transitions.dev tabs-sliding. `--duration-fast` 250ms, `--ease-smooth-out`,
  symmetric. Same tokens the format rule uses, so the two tablists converge.
- Suspend the transition on the first write or it flies in from zero on every mount.
- **Strobe-safe by construction.** It is a transition on `transform`, so a held arrow key
  produces one continuous slide that retargets. Strictly better than today's seven
  overlapping colour fades. Anything keyframe-based restarts every 30-90ms and finishes
  nothing, which is the failure `GalleryControls.tsx:69` already throttles for.
- **One build-time check:** tweening `background-color` between tints produces unmeasured
  intermediate colours, and DESIGN.md §6 says the tints were measured for AA. Set the
  capsule's colour to the destination tint **instantly** and animate only the transform.
  Every frame then shows one of the seven measured tints. Assert it in `contrast.spec.ts`.

## BATCH 3 — Motion · DONE 2026-09-04

All 13 applied. Notes on the two that changed behaviour enough to move tests:

- **The grid wave is DEBOUNCED, not keyed on the category.** The filter stays
  instant; only the animation waits 80ms (`--duration-micro`, which is
  transitions.dev's documented intent-delay beat and was one of the three dead
  tokens this batch was going to delete). A fast scrub now swaps with no
  animation, which is what a scrub should look like.
- **The reveal's settle timer fires at 0 under reduced motion.** The CSS already
  zeroed the delays, but a JS timer held the UNMERGED per-cell render for the
  full 530ms — and `layoutCells` merges runs precisely to remove the
  anti-aliasing seam. So the picture arrived with seams and re-knitted half a
  second later, which is a motion event for someone who asked for none. The
  reduced-motion test asserted the old behaviour and now asserts the merged
  picture arriving with no scatter at all.

Two tests needed timing changes rather than fixes: the drum's tracking test
sampled faster than the 45ms follow bridge it just gained, and the category-swap
test read for a running animation before the 80ms debounce had fired.

`--distance-base` was deleted; `--ease-bounce` survives as documented policy in
§5b even though nothing reads it, and `--duration-micro` now has a consumer.

## BATCH 4 — Copy polish and doc drift · DONE 2026-09-04

- **The search placeholder is `Search by name or tag`.** The useful half was
  hidden in the accessible name, where sighted users never see it, and the
  field's own glyph already said "search". It now matches the composer's import
  picker, which has said this all along.
- **The empty state links to Contribute.** It dead-ended: the reset undoes the
  search and returns you to where you were, and that was the only move on offer.
  Quiet and second, because most failed searches are a typo — but at 24 icons a
  genuine gap is the more likely of the two. The stronger version the audit
  named, a GitHub issue prefilled from the query, was NOT built: it sends people
  off-site from a dead end, and `/contribute` already carries that link with the
  context around it.
- Status pills are sentence case on both pages (`Planned`, not `planned`).
- `Copy Data URI` now confirms as `Data URI copied`. The NOUN may still differ
  between a tab and a toast — `React` against `React component` — because a
  sentence can afford the extra word; recasing the same noun was the defect.
- `GalleryControls` no longer maintains the swatch's label twice.
- The `--engrave` comment claimed the category chips read it. They never have;
  its readers are the size rail's numbers and the drum's faces.

Two items were already closed in earlier batches: the PNG failure gained a next
step in Batch 2, and the stale `.pixl-field` comment went with the rebuild in
Batch 1.

### Original notes, for the record

Lowest priority. Judgment calls, not defects.

- **The search placeholder.** `Search icons…` hides its useful half in the `aria-label`
  (`Search icons by name or tag`), where sighted users never see it. Candidates:
  `Search by name or tag` (matches the composer's picker, lowest risk);
  `arrow, folder, heart…` (teaches the tag vocabulary by example);
  `Search 24 icons` (names the set's size, read from `icons.length`). Drop the ellipsis either way.
- **The empty state's hint line** gives abstract advice and a fact about the data model.
  Candidates: `Every icon is tagged. Try one word: arrow, media, folder.`;
  `Search matches names and tags. A shorter word usually finds more.`; or delete it and let
  the button carry it.
- **A failed search is the best moment in the product to reach Contribute**, and the empty
  state links nowhere. A prefilled `Request "shopping-cart" on GitHub` turns the set's
  biggest weakness at 24 icons into its acquisition moment. Product change, not copy.
- Two search placeholders differ across surfaces (`GalleryToolbar.tsx:59` vs `ImportPicker.tsx:99`).
- Status pills use two conventions: `planned` vs `Not open yet`.
- The formats menu says `Copy Data URI`; the toast says `data URI copied`. Noun and case both change.
- The PNG failure has no next step; its sibling does.
- `GalleryControls.tsx:206`/`213` maintain the same string twice, which is how one got fixed and the other did not.
- **`globals.css:984` claims `--engrave` is used by the category chips. It is not.** Grep finds it at `1902` and `4080` only.
- **The stale `.pixl-field` comment** at `globals.css:936` describes the retired architecture. Delete it; it is the evidence for this whole audit and it should not survive the fix.

  visually, this survives intact.
- axe finds **0 violations** scoped to these two elements, both themes.
- The detector finds **0 issues** across `src/components/gallery`.
- Sentence case is consistent across every button, heading and label in the product.
- The toast component's two-tone system is correct. Only the gallery's wiring to it is wrong.
